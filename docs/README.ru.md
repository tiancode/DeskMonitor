# DeskMonitor

[简体中文](../README.md) · [繁體中文](README.zh-Hant.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [Español](README.es.md) · [Português (BR)](README.pt-BR.md) · **Русский** · [Italiano](README.it.md)

Плавающий виджет рабочего стола для macOS, показывающий в реальном времени
**CPU / GPU / память / чтение и запись диска / сетевой трафик**.
Нативный SwiftUI, один процесс, без зависимостей, все данные берутся через низкоуровневые
системные API — **sudo не нужен**.

## Сборка и запуск

```bash
./build.sh              # сборка + упаковка + ad-hoc подпись
open DeskMonitor.app
```

`DeskMonitor --probe` печатает 5 циклов замеров обычным текстом — удобно сверять с «Мониторингом
системы» или `top`.

## Управление

Программа не занимает место в Dock и **по умолчанию в строке меню тоже** — все настройки лежат в
меню, которое открывается **правым щелчком по панели**.

| Действие | Как |
|---|---|
| Переместить | Тяните панель за любое место (позиция запоминается, привязка при этом снимается) |
| Привязка к углу | Правый щелчок → Привязка к углу: Слева вверху / Справа вверху / Слева внизу / Справа внизу / Свободное размещение |
| Уровень окна | Правый щелчок → Уровень окна: На рабочем столе / Обычное окно / Поверх всех окон |
| Интервал | Правый щелчок → Интервал обновления: 0,5 / 1 / 2 / 5 с |
| Непрозрачность | Правый щелчок → Непрозрачность: 50% / 70% / 85% / 100% |
| Значок в строке меню | Правый щелчок → Показывать значок в строке меню (по умолчанию выключен) |
| Запуск при входе | Правый щелчок → Запускать при входе |
| Выход | Правый щелчок → Завершить |

Если угол выбран, панель возвращается к нему после смены монитора или разрешения.
Когда значок в строке меню выключен, пункта «Скрыть панель» в меню нет: скрытую панель было бы
нечем вернуть.

Уровень по умолчанию — «На рабочем столе»: над обоями и значками рабочего стола, под окнами других
программ. Именно так и должен вести себя виджет рабочего стола. Чтобы панель была видна всегда,
переключитесь на «Поверх всех окон».

## Источники данных

| Показатель | API | Примечание |
|---|---|---|
| CPU | `host_processor_info(PROCESSOR_CPU_LOAD_INFO)` | Счётчики тиков по ядрам, разность двух замеров — тот же источник, что у «Мониторинга системы» |
| GPU | IORegistry `IOAccelerator` → `PerformanceStatistics` | На Apple Silicon без root; sudo требует как раз `powermetrics` |
| Память | `host_statistics64(HOST_VM_INFO64)` + `vm.swapusage` | Занято = приложения + связанная (wired) + сжатая, как в «Мониторинге системы» |
| Давление памяти | `kern.memorystatus_vm_pressure_level` | Большое «занято» само по себе не означает нехватку — реальный сигнал это давление |
| Диск | IORegistry `IOBlockStorageDriver` → `Statistics` | Разность накопленных байтов ÷ интервал = текущая скорость |
| Ёмкость | `statfs` | Свободно / всего на загрузочном диске, те же числа, что у `df` |
| Сеть | `sysctl(NET_RT_IFLIST2)` → `if_data64` | Байты основного интерфейса; какой он — говорит PrimaryInterface из `SCDynamicStore` |

Два источника, которые легко прочитать неверно:

**`In use system memory` из `IOAccelerator` — это не видеопамять.** При единой памяти значение идёт
за системной памятью и на машине с 512 ГБ показывает больше 300 ГБ. Поэтому в строке GPU выводится
только загрузка и недавний пик.

**Счётчики байтов интерфейса несут только младшие 32 бита.** Значения `ifi_ibytes` / `ifi_obytes`,
которые программа читает из `NET_RT_IFLIST2`, усечены: полные 64 бита достаются только процессам с
подписью Apple. Поэтому приращения считаются по модулю 2³² — результат верен, пока за один интервал
замера проходит меньше 4 ГБ. Абсолютным значениям доверять нельзя, так что итоги сеанса
накапливаются из приращений.
